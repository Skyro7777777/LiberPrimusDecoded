Onion 3 (ver 4?) 2 different strings and extracted images with runes

At 2014-01-11 22:07:12 UTC, Onion3 briefly (for 14 minutes) published a long (~4.2 MB) string which contained a hexdump. Two jpg images could be extracted from that string:

onion3.image00.jpg: Beginning at position 0 in normal byte order, size: 871.8 KB. The image shows a page of runetext. OutGuess finds a hidden message which is a signed hexdump of another jpg (onion3.image00.outguess.jpg). The signature is valid.

onion3.rev.image.jpg: After reversing the byte-order of the hexdump another image (1.2 MB) can be found. OutGuess finds no readable message, but it can produce some output in certain cases even if no message was hidden. Maybe this seemingly random data becomes important later on.

All three images (the two from the onion hexdump and the one found via outguess) contain some runetext which has been transcribed at http://pastebin.com/aeEak0XB

Finally, the pages were translated and decrypted. All information about this can be found here.

Solution of page 4 and page 5 from Liber Primus book.

It was discovered the encryption used in the 4th and 5th page of the book was a Vigenère cipher with the keyword "DIVINITY" (how? ), obviously represented by runes. "DIUINITY" results from using 6, 19, 28, 19, 20, 19, 13, 3 shifts in the reversed Gematria Primus [image]  from top to bottom (there's no "V" in the Gematria Primus so it is an assumption "U" == "V").  -See this picture if you still have trouble understanding this-

After wasting two hours of my life trying to recreate the results posted here using the standar Vigenere table provided by SepheusIX, I analyzed what was actually happening.  So it appears they used an inverted (or reversed) Vigenere table, so I made one in a spreadsheet.  Using this table, all the letters coincide with the encrypted pages (5th and 6th), including the onion address, but still no explanation why the password was "DIVINITY" or why the character "F" is ignored and reset the key for decryption.
