    85→### 2.1 The Autokey / Autoclave Hypothesis (community consensus 2024–2025)
    86→
    87→**Source:** Uncovering Cicada wiki "Frequency Analysis Unsolved Pages" + UATrav interview of UALR cryptography professor Tran Phuong + CicadaSolvers quickstart briefing.
    88→
    89→**Evidence:** The doublet occurrence rate across all 56 unsolved LP2 pages is **0.663%** (86 doublets in 12,956 runes), versus **3.45%** expected for random text (1/29). This is a 5× reduction. Pure Caesar / Vigenère / Rot13 would *preserve* the doublet rate (since they preserve the underlying plaintext distribution). An autokey / autoclave cipher (where the key stream depends on prior plaintext or ciphertext) suppresses doublets because the same plaintext letter can no longer encrypt to the same ciphertext letter at neighbouring positions.
    90→
    91→**Quote from Grant Kortfelt (CicadaSolvers member, WPI CS senior) in UATrav:**
    92→> "We just know at some point in the encryption algorithm, the current rune being encrypted knows the cipher text of the one before it."
    93→
    94→**Comparison drawn:** to WWII Enigma, which was broken because "an encrypted letter could never appear as the letter it represented" — i.e., the LP cipher appears to have a similar "no-adjacent-doublet" property.
    95→
    96→**Implication for the dossier's §9 hypotheses:** Hypothesis 1 ("keyed Vigenère with key derived from LP itself") is partially correct but is now refined to **"autokey Vigenère whose key stream is itself the previously-seen plaintext/ciphertext rune sequence"** (likely seeded by a small primer key whose candidate material is the dossier's listed key list — DIVINITY, FIRFUMFERENFE, the Parable, the magic squares, etc.).

   140→### 2.4 Single-rune word constraints (new cribbing info)
   141→
   142→From CicadaSolvers briefing: in LP1 and LP2 there are many single-rune words. These can *ostensibly* only be "A" or "I" in Latin (with "O" as a less-likely Blake-style interjection). Multi-letter runes (TH, EO, NG/ING, OE, AE, IA/IO, EA) complicate cribbing. This is a useful cribbing constraint: if a single rune in the plaintext is letter N, it must equal one of these Latin values.
   143→
   144→### 2.5 Character Interchangeability (new)
   145→
   146→CicadaSolvers briefing: "There is strong evidence to support the encryption was performed on the runes instead of the Latin characters. This is due to not being able to go back and forth between runes and Latin characters." Example: ᛏᚻᚫᛡ → THAEIO → ᚦᚫᛡ (lossy — the round-trip is not the identity). Confirms the dossier's "decryption is many-to-one" note, and means **cipher operations must be performed mod-29 on rune-decimal values, not on Latin letter indices** — invalidating any tool that converts runes to Latin letters before applying cipher math.

   301→### Hypothesis 8 (NEW): Autokey Vigenère with primer derived from solved-page keys
   302→The cipher is an **autokey Vigenère** where the running key is `primer_key || plaintext[0..n-1]` (or `primer_key || ciphertext[0..n-1]`). The primer key is one of the dossier's listed candidates (DIVINITY, FIRFUMFERENFE, the Parable text, the magic-square numbers, or one of the new candidates from §3 above — the onion cookies, the 154-digit P.S. number, or the missing-primes sequence).

   304→**Evidence:** §2.1's doublet-suppression signature is the textbook fingerprint of an autokey cipher. Autokey is the natural extension of Vigenère once F-skip is applied; it is also the historical descendant of the Trithemius cipher, fitting Cicada's classical-cipher aesthetic.
   305→
   306→**Attack:** Implement a length-k autokey Vigenère solver (k = primer length) using simulated annealing / hill-climbing on English-likeness score (IOC, quadgram log-probability, vowel ratio). The primer-key candidates form a small finite set, so the search space is tractable.
   307→
   308→### Hypothesis 9 (NEW): Prime-Fibonacci meshed stream cipher
   309→The cipher is a *generalisation* of the page-56 prime-stream cipher. Instead of shifting by `(prime[i] − 1) mod 29`, it shifts by a meshed sequence where primes and Fibonacci numbers interleave per Cicada's documented preference (§2.7). Possible formulations:
   310→- `shift[i] = (prime[i] − 1 + fib[i]) mod 29`
   311→- `shift[i] = (prime[fib[i]]) mod 29` — prime-indexed-by-Fibonacci
   312→- `shift[i] = prime[i] mod 29` if `i` even, `fib[i] mod 29` if `i` odd
   313→- `shift[i] = (φ(prime[i]) + φ(fib[i])) mod 29` — totients
   314→
   315→**Evidence:** The 15.jpg square reconstruction (§2.6) and the 2015/2016/2017 message GP-sum pattern (§2.7) both point to a prime-Fibonacci mesh.

   318→Based on the `lp-decrypter` repo description: *"generic LP decrypter 1: functions of two runes"*. This implies the cipher may operate on rune-PAIRS rather than individual runes — i.e., a Playfair-style digraphic substitution over the 29-rune alphabet. Playfair-class ciphers naturally suppress doublets (because the same plaintext symbol cannot appear twice in the same digraph in classical Playfair), which would partially explain the §2.1 doublet suppression.

   320→**Evidence:** Repo description; autokey-signature could be partially explained by digraphic structure.
